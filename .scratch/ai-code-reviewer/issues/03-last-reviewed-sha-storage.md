## Question

`idea.md` §2 says the bot stores the last-reviewed commit SHA in a "hidden/system
note on the MR itself", so the ephemeral job needs no external storage.

Confirm what is actually possible for a bot account through GitLab API v4:

- Can an API client create a *system* note? (System notes are normally generated by
  GitLab itself, not posted by users — verify this.)
- Is there any hidden, non-user-visible note or metadata channel available? Check
  confidential notes, MR-level custom attributes, and any label or description field
  a bot could write to.
- If nothing hidden exists, what are the honest options — a visible marker comment,
  an HTML-comment marker inside the summary comment, or reading the SHA back off the
  bot's own prior comments?
- Whichever channel is available: can it be read reliably and cheaply at job start?

If the doc's stated mechanism turns out not to exist, say so plainly. Per the map's
Notes, that gets raised rather than quietly redesigned. This also feeds the feedback
correlation ticket, which needs the same answer about marker metadata.
